# Plan: RAG Pipeline

**Domain:** AI
**Priority:** 4 (enables FAQ, enhances Life Preview, enables Application Q&A)
**Status:** Draft
**Depends on:** Pets (Phase 3), AI infrastructure (Phase 5 base, specifically `Ai::Provider` adapter), Life Preview (specs/10 — `Ai::GenerateLifePreview`, prompt v2, caching)

---

## Overview

The **RAG (Retrieval-Augmented Generation) Pipeline** adds a shared vector search infrastructure that powers three features:

1. **Shelter Policy FAQ** — Visitors on a shelter profile ask natural-language questions and get answers grounded in the shelter's uploaded policy documents.
2. **Life Preview Enhancement** — The existing `Ai::GenerateLifePreview` (specs/10) fetches relevant shelter policy chunks as additional context, making generated previews shelter-aware.
3. **Adoption Application Q&A** — Adopters (and shelter staff) ask questions about a specific application and get answers grounded in application data + shelter policies.

All three share the same core: **pgvector** for storage, a provider-agnostic embedding service, a chunker, a vector search, and a query engine that assembles context for the LLM.

## Requirements

### R1: Shelter Policy FAQ

The shelter profile page shall allow visitors to ask natural-language questions about the shelter's policies and receive AI-generated answers grounded in the shelter's uploaded documents.

**Scope:**
- Public endpoint (no auth required)
- Answers cite shelter documents only (not general web knowledge)
- Display answer inline below the question input
- Loading state during generation
- Error state with retry on failure
- Rate-limited per IP (configurable)

**Answer quality:**
- Answers must be grounded in retrieved chunks — if no relevant chunk found, respond: "I couldn't find information about that in this shelter's policies. Contact the shelter directly for more details."
- Include a subtle disclaimer: "This answer was generated by AI based on this shelter's policy documents."
- Answers should be concise (2-4 sentences) with optional bullet points for structured info.

### R2: Life Preview RAG Enhancement

The existing `Ai::GenerateLifePreview` service object (specs/10) shall additionally query the vector store for shelter policy chunks relevant to the pet, and include them as `{{shelter_policy_context}}` in the prompt.

**Behavior:**
- When generating a life preview, embed the pet's breed/species/description
- Vector search limited to the pet's shelter
- Include up to 5 relevant chunks as "Shelter Policy Context" in the prompt
- The generated preview should reference shelter-specific policies where relevant (e.g., "This shelter requires a home visit — schedule that in Week 0")
- If no relevant chunks found (no documents uploaded), the prompt variable is replaced with "None provided." — generation proceeds normally

### R3: Adoption Application Q&A

Adopters (via their application token) and shelter staff (via session) can ask questions about a specific adoption application and receive answers grounded in the application data, timeline events, notes, and shelter policies.

**Scope:**
- Authenticated endpoint (token-based for adopters, session-based for staff)
- Sources: adoption_application record, adoption_timeline_events, adoption_notes, shelter policy documents (RAG)
- Answers reference specific data from the application (e.g., "Your application was received on June 20th and is currently under review.")
- Shelter staff can use this to quickly review application context

**Authorization model:**
- Adopter: access via application token (the same token used for the public status page)
- Shelter staff: access via Pundit policy (`record.shelter_id == current_user.shelter_id`)
- Answers never reveal other applicants' data

#### `Ai::Rag::VectorSearch`

```ruby
# lib/ai/rag/vector_search.rb
module Ai
  module Rag
    class VectorSearch < ApplicationService
      def initialize(embedding, scope: nil, limit: 5)
        @embedding = embedding
        @scope = scope     # ActiveRecord relation filter (e.g., by shelter_id)
        @limit = limit
      end

      def call
        relation = Ai::DocumentChunk.all
        relation = relation.merge(scope) if scope
        relation.nearest_neighbors(:embedding, @embedding, distance: :cosine)
                 .limit(@limit)
      end
    end
  end
end
```

Uses pgvector's `cosine` distance for similarity search. The `scope` parameter allows filtering by shelter (or other dimensions) before the ANN search.

#### `Ai::Rag::QueryEngine`

```ruby
# lib/ai/rag/query_engine.rb
module Ai
  module Rag
    class QueryEngine < ApplicationService
      def initialize(question:, context_chunks:, system_prompt_name: "rag_faq", extra_variables: {})
        @question = question
        @context_chunks = context_chunks
        @system_prompt_name = system_prompt_name
        @extra_variables = extra_variables
      end

      def call
        prompt = Ai::PromptBuilder.call(
          prompt_name: @system_prompt_name,
          variables: prompt_variables
        )
        Ai::Provider.call(prompt: prompt)
      end

      private

      def prompt_variables
        {
          question: @question,
          context: formatted_context,
          disclaimer: "This answer was generated by AI based on available information."
        }.merge(@extra_variables)
      end

      def formatted_context
        @context_chunks.map.with_index(1) do |chunk, i|
          "[Document #{i}]: #{chunk.content}"
        end.join("\n\n")
      end
    end
  end
end
```

```ruby
  class ProcessDocumentJob < ApplicationJob
    queue_as :ai
    retry_on StandardError, attempts: 3, wait: :exponentially_longer

    def perform(document_id)
      document = Ai::Document.find(document_id)
      return unless document.status == "processing"

      if document.source_type == "pdf"
        extract_text_from_pdf(document)

      texts = chunks.map { |c| c[:content] }
      embeddings = Ai::Rag::EmbeddingService.call(texts)

          document.chunks.create!(

            chunk_index: chunk[:index],
            embedding: embeddings[i]
```

### Shareable RAG Query Flow

All three use cases follow the same general flow, with different inputs:

```
Input: question + scope (shelter_id / application context)
         │
         ▼
1. Embed the user's question
         │
         ▼
2. Vector search: find top N chunks within scope
         │
         ▼
3. Build context from chunks + any structured data
         │
         ▼
4. QueryEngine: system prompt + context + question → LLM
         │
         ▼
5. Return answer to caller
```

**Shelter FAQ:**
- Scope: `Ai::DocumentChunk.joins(:ai_document).where(ai_documents: { shelter_id: params[:shelter_id] })`
- No extra structured data
- Uses `config/prompts/rag_faq.yml`

**Life Preview RAG:**
- Scope: same shelter filter
- Embed: pet breed + species + description (not the user's question)
- Extra variables: the chunks are added as `{{shelter_policy_context}}` in `life_preview.yml` prompt
- Called from within `Ai::GenerateLifePreview.call`

**Application Q&A:**
- Scope: shelter policy chunks (same as FAQ) + application data (structured)
- Extra variables: application status, timeline summary, notes summary
- Uses `config/prompts/rag_application_qa.yml`

### Controllers

**`Ai::RagQueriesController`** (dual-purpose: shelter FAQ + application Q&A)

```ruby
# app/controllers/ai/rag_queries_controller.rb
module Ai
  class RagQueriesController < ApplicationController
    # POST /shelters/:shelter_id/rag_queries
    # POST /adoption_applications/:adoption_application_id/rag_queries
    def create
      if params[:shelter_id]
        handle_shelter_query
      elsif params[:adoption_application_id]
        handle_application_query
      end
    end

    private

    def handle_shelter_query
      @shelter = Shelter.undiscarded.find(params[:shelter_id])
      authorize @shelter, :show?

      question = params[:question]
      return render json: { error: "Question required" }, status: :unprocessable_entity if question.blank?

      result = perform_rag_query(
        question: question,
        scope: Ai::DocumentChunk.joins(:ai_document)
                                .where(ai_documents: { shelter_id: @shelter.id }),
        prompt_name: "rag_faq"
      )

      render json: { answer: result }
    end

    def handle_application_query
      @application = AdoptionApplication.find_by!(token: params[:adoption_application_id])
      authorize @application, :show?

      question = params[:question]
      return render json: { error: "Question required" }, status: :unprocessable_entity if question.blank?

      shelter_scope = Ai::DocumentChunk.joins(:ai_document)
                                       .where(ai_documents: { shelter_id: @application.shelter_id })

      timeline_summary = @application.timeline_events.order(:created_at).pluck(:event_type, :created_at)
      notes_summary = @application.notes.recent.limit(5).pluck(:content)

      result = perform_rag_query(
        question: question,
        scope: shelter_scope,
        prompt_name: "rag_application_qa",
        extra_variables: {
          application_status: @application.status,
          application_submitted_at: I18n.l(@application.created_at.to_date),
          pet_name: @application.pet.name,
          pet_species: @application.pet.species,
          pet_breed: @application.pet.breed.presence || "Mixed",
          application_timeline: timeline_summary.map { |e, t| "#{e} (#{I18n.l(t.to_date)})" }.join(", ").presence || "No events yet",
          application_notes: notes_summary.join("\n").presence || "No notes yet"
        }
      )

      render json: { answer: result }
    end

    def perform_rag_query(question:, scope:, prompt_name:, extra_variables: {})
      embedding = Ai::Rag::EmbeddingService.call(question)
      chunks = Ai::Rag::VectorSearch.call(embedding: embedding, scope: scope, limit: 5)
      Ai::Rag::QueryEngine.call(
        question: question,
        context_chunks: chunks,
        system_prompt_name: prompt_name,
        extra_variables: extra_variables
      )
    end
  end
end
```

**Stimulus controller:**

```js
// app/javascript/controllers/faq_controller.js
import { Controller } from "@hotwired/stimulus"

export default class extends Controller {
  static targets = ["input", "answer", "loading", "content", "error"]
  static values = { shelterId: Number, applicationToken: String }

  ask() {
    const question = this.inputTarget.value.trim()
    if (!question) return

    this.answerTarget.classList.remove("hidden")
    this.loadingTarget.classList.remove("hidden")
    this.contentTarget.classList.add("hidden")
    this.errorTarget.classList.add("hidden")

    const url = this.applicationTokenValue
      ? `/adoption_applications/${this.applicationTokenValue}/rag_queries`
      : `/shelters/${this.shelterIdValue}/rag_queries`

    fetch(url, {
      method: "POST",
      headers: { "Content-Type": "application/json", "X-CSRF-Token": document.querySelector("[name='csrf-token']").content },
      body: JSON.stringify({ question })
    })
      .then(r => r.json())
      .then(data => {
        this.loadingTarget.classList.add("hidden")
        this.contentTarget.classList.remove("hidden")
        this.contentTarget.innerHTML = data.answer
      })
      .catch(() => {
        this.loadingTarget.classList.add("hidden")
        this.errorTarget.classList.remove("hidden")
      })
  }
}
```

### Life Preview RAG Integration

Modified flow in `Ai::GenerateLifePreview`:

```ruby
# Inside Ai::GenerateLifePreview#call (after loading pet data)
def fetch_shelter_policy_context
  query_text = [
    @pet.species,
    @pet.breed,
    @pet.description&.truncate(500),
    @pet.personality_traits_list.join(", ")
  ].compact.join(" ")

  embedding = Ai::Rag::EmbeddingService.call(query_text)
  chunks = Ai::Rag::VectorSearch.call(
    embedding: embedding,
    scope: Ai::DocumentChunk.joins(:ai_document)
                            .where(ai_documents: { shelter_id: @pet.shelter_id }),
    limit: 5
  )

  chunks.map(&:content).join("\n\n").presence || "None provided."
end
```

The resulting context gets added to the prompt variables as `shelter_policy_context`.

### Caching

**FAQ answers:** Cache identical question + shelter_id combinations for 1 hour. Key: `rag_faq/#{shelter_id}/#{Digest::MD5.hexdigest(question)}`.

**Application Q&A:** Do not cache (contains personal/sensitive data).

**Document processing status:** Cached on the `ai_documents.status` column directly.

## Risks & Unknowns

| Risk | Impact | Mitigation |
|------|--------|------------|
| Embedding API cost at scale | Medium | Cache FAQ answers. Batch embed during document processing (not per query). |
| pgvector query performance | Low for MVP | Start without index (<10K rows). Add ivfflat index when needed. |
| PDF parsing quality | Medium | Some PDFs have non-extractable text (scanned images). Document with clear expectations. |
| FAQ answer quality | Medium | Tight system prompt grounding. If no chunks match, redirect to contact shelter. |
| Hallucination in RAG answers | Medium | Strict grounding prompt. Disclaimer on all answers. |
| Embedding dimension changes (provider switch) | Medium | Store dimension in config. Re-embed all docs on provider change. |
| Concurrent document processing | Low | Sidekiq processes one job at a time per document (unique by ID). |
